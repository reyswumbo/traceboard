🚀 TRACEBOARD ANDROID APP CHALLENGE

Build Traceboard — Clipboard, Writing & Usage Analytics

We’re challenging everyone — developers, beginners, and AI-assisted builders — to create Traceboard, a modern native Android utility application that combines clipboard management, writing statistics, keyword tracking, and application usage analytics in one clean experience.

You do not need a professional developer background to participate.

AI assistance is fully allowed.

---

🎯 THE CONCEPT

Traceboard is a personal productivity and activity-tracking utility designed around three main areas:

📋 Clipboard

Automatically save copied text into the application.

✍️ Writing

Track words, characters, and selected keywords while the user writes.

📊 Usage

Analyze how much time the user spends using applications and provide usage statistics.

The application should feel like one polished product, not several unrelated tools combined together.

---

📋 CLIPBOARD MANAGER

Traceboard must be able to automatically save text copied by the user.

▶️ START BUTTON

Clipboard recording should have a clear Start button.

When the user presses:

«Start»

Traceboard begins monitoring and saving newly copied text.

When recording is active, the application should clearly indicate that clipboard tracking is running.

The user should also be able to stop recording.

Saved Clipboard Items

Every copied text entry can be:

- Saved automatically
- Viewed
- Edited
- Deleted
- Copied again
- Organized neatly
- Imported
- Exported

The clipboard history should be presented in a clean and easy-to-use interface.

---

📦 IMPORT & EXPORT

Clipboard data must be able to be exported and imported so users can keep their data from being lost.

The implementation may use an appropriate format such as:

- JSON
- TXT
- CSV
- Another reasonable structured format

The exported data should contain enough information to restore the clipboard entries.

Example:

Traceboard Backup

Clipboard Entries
├── Entry 1
├── Entry 2
├── Entry 3
└── Entry 4

Users should be able to:

Export → save backup → reinstall/change device → Import → restore data

The application should handle invalid or corrupted import files gracefully.

---

✏️ EDIT CLIPBOARD TEXT

Users must be able to edit saved clipboard entries.

For example:

Original:

«Hello World»

User edits it to:

«Hello World!»

The updated text should be saved.

Users should also be able to delete individual entries.

A confirmation dialog may be used for destructive actions where appropriate.

---

🔍 SEARCH & ORGANIZATION

The clipboard section should provide a convenient way to find saved text.

Recommended:

- Search
- Sorting
- Recent items
- Long text handling
- Copy button
- Delete
- Edit
- Import
- Export

The interface should remain clean even when the user has a large number of clipboard entries.

---

✍️ WRITING & WORD ANALYTICS

Traceboard must provide a dedicated Writing section.

Users can enter or write text inside the application.

The application should analyze the text in real time.

---

🏷️ TRACKED WORDS

Users can manually add words they want Traceboard to track.

For example, the user adds:

«maaf»

Traceboard should count every occurrence of the word regardless of capitalization.

For example:

«maaf
Maaf
MAAF
MaAf»

All of these should be counted as:

«maaf — 4×»

Case should not affect the count.

---

📝 WRITING EXAMPLE

If the user writes:

«maaf maaf»

Traceboard should recognize:

- "maaf" → 2×
- Total words → 2

The application should also calculate the total number of characters.

For example:

«"maaf maaf"»

contains:

- 2 words
- 8 letters
- 9 characters including the space

The exact counting rules should be clearly documented in the README.

---

➕ ADD TRACKED WORDS

Users should be able to add as many words as they want to monitor.

Example:

Tracked Words

maaf       12×
terima      8×
halo        5×
terima kasih 3×

Users should be able to:

- Add tracked words
- Remove tracked words
- Edit tracked words
- View their counts
- Reset counts where appropriate

Tracking should work in real time while the user writes.

📱 APPLICATION USAGE ANALYTICS

Traceboard must also provide a dedicated section for application usage statistics.

This feature should work independently from the Clipboard Start button.

Important:

«Users do NOT need to press Start to collect application usage statistics.»

The usage statistics should be based on the Android system's available application usage information and permissions.

---

⏱️ USAGE TIME

Traceboard should show how much time the user has spent using applications.

Provide selectable time periods:

Today

Usage during the current day.

7 Days

Usage during the previous 7 days.

1 Month

Usage during the previous month.

All Time

Available accumulated usage data.

---

🕐 PRECISE TIME

Usage time should be displayed using an appropriate level of precision.

For example:

«199 hours 24 minutes 17 seconds»

or:

«24 minutes 32 seconds»

Depending on the duration.

Users should be able to view:

- Hours
- Minutes
- Seconds

The application should avoid displaying misleading rounded values when more precise information is available.

---

📱 APP-BY-APP STATISTICS

Users should be able to see individual application usage.

Example:

Application Usage

YouTube
199h 24m 17s

Chrome
82h 14m 32s

Instagram
47h 52m 09s

Telegram
31h 18m 42s

Each application should display its total usage time.

Users should be able to open an individual application entry to view more detailed statistics.

---

🏆 MOST USED APPLICATIONS

Traceboard should identify applications that consume the most usage time.

For example:

Most Used

1. YouTube       199h 24m
2. Chrome         82h 14m
3. Instagram      47h 52m
4. Telegram       31h 18m

The list should automatically update according to the selected time period.

---

🔋 BATTERY & STORAGE INFORMATION

Where Android permissions and APIs allow it, Traceboard may provide additional device statistics such as:

🔋 Battery

Show applications that have consumed the most battery.

Example:

Battery Usage

💾 Storage

Show applications that consume the most storage.

Example:

If a particular statistic cannot be obtained reliably through standard Android APIs, the application should not fabricate the data.

The application should clearly explain unavailable information.

For example:

A refresh mechanism may also be provided.

🔐 PERMISSIONS & PRIVACY

The application must clearly explain why each sensitive Android permission is required.

For example, if application usage statistics require a specific Android permission or user-enabled access, the application should provide a clear explanation and guide the user through the process.

Do not request unnecessary permissions.

The application should follow the principle:

«Only request the permissions that are actually required.»

Participants should also clearly document permission requirements in the README.
